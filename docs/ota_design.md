# OTA 预留设计

## 1. 当前状态

当前项目主线已经实现：

```text
ESP32-S3 → MQTT → Linux Gateway → STM32F407 → PCA9685 → MG90S
```

OTA 当前作为后续工程化增强功能预留，不强行在 Day29 实现。

---

## 2. 为什么需要 OTA

在真实 AIoT 项目中，设备部署后不方便频繁拆机烧录固件，因此需要 OTA 远程升级能力。

ESP32-S3 作为智能眼镜控制端，后续可以通过 OTA 更新：

1. 手势识别算法
2. MQTT Topic 配置
3. OLED UI 显示逻辑
4. WiFi / Broker 配置
5. 命令发布策略
6. 稳定性优化逻辑

---

## 3. ESP32 OTA 分区设计

后续可以采用如下分区结构：

```text
factory：出厂固件
ota_0：OTA 固件槽 0
ota_1：OTA 固件槽 1
ota_data：记录当前启动分区
```

设计思想：

```text
factory 用于保留出厂固件
ota_0 / ota_1 用于双分区升级
ota_data 用于记录当前应该从哪个 OTA 分区启动
```

---

## 4. OTA 升级流程

```text
服务器发布新固件
        ↓
ESP32-S3 检查版本号
        ↓
下载新固件
        ↓
写入 ota_0 / ota_1
        ↓
校验固件完整性
        ↓
切换启动分区
        ↓
重启进入新固件
        ↓
运行成功后确认新版本
```

## 5. OTA 可升级内容

| 模块 | 可升级内容 |
|---|---|
| gesture | 手势识别阈值和算法 |
| mqtt_sender | Broker 地址、Topic、发布策略 |
| oled_ui | 显示界面 |
| command | 手势到命令的映射 |
| wifi_manager | WiFi 连接策略 |
| app_main | 主流程和稳定性逻辑 |

## 6. OTA 风险和保护

OTA 需要考虑：

```text
1. 下载中断
2. 固件校验失败
3. 新固件启动失败
4. WiFi 中途断开
5. 电量不足
```

后续可加入：

```text
1. 固件版本号
2. 固件校验
3. 回滚机制
4. 升级进度显示
5. OTA 状态 MQTT 上报
```
