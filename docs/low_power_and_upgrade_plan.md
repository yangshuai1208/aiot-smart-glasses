
# AIoT 姿态感知机械手控制系统：低功耗与工程化升级计划



## 1. 项目目标与现状

### 1.1 现有主链路

```text
MPU6050 ─I2C─> ESP32-S3 ─Wi-Fi/MQTT─> Broker ─> Linux Gateway
                                                        │
                                                      UART
                                                        │
                                                        ▼
STM32F407 ─I2C─> PCA9685 ─PWM─> MG90S × 5
```

- ESP32-S3：姿态采集、阈值识别、按键、OLED反馈；MQTT发布是主控制通道，UART JSON仅作调试/备用。
- Linux Gateway：接收控制消息、解析并转换命令，经UART下发执行端。独立网关仓库中的串口采集→JSON→MQTT及C++并发/可靠通信实验应与主链集成功能区分。
- STM32F407：接收 `HAND_*` 命令，通过PCA9685控制5路舵机，已有角度限幅、平滑步进和STOP安全位（约90°）。当前动作过程含阻塞等待，**STOP尚不等于可立即抢占的硬件急停**。
- OTA：ESP32-S3基础分区查询与写入接口已开展；完整下载、板载升级、重启确认及回滚按实测验收后再勾选。
- ROS2：Humble最小Demo已做；与网关和STM32的真实控制/状态闭环尚需集成验证。
- ACK/seq/超时重试/去重：已有独立实验或局部设计，不能直接描述为已在整条实机链路完整落地。
- **低功耗优化尚属计划**，本文不填写未经测量的节电百分比。

### 1.2 本轮升级目标

1. **可靠性**：从“能发命令”进化为“可校验、可确认、可重试、可定位故障”。
2. **实时响应**：用非阻塞动作状态机提高STOP响应能力。
3. **可维护性**：模块接口清晰，日志、错误码、文档和验收记录齐全。
4. **低功耗**：在不牺牲控制安全的前提下优化待机和空闲能耗。
5. **可扩展性**：增加传感器反馈及ROS2最小控制/状态链路。

## 3. 低功耗优化专项

### 3.1 安全和实时性约束

- **控制中的STOP优先级高于节能**。正在执行动作或需保持夹持力时，不主动关闭相关控制/供电。
- ESP32-S3进入Deep-sleep会失去当前Wi-Fi/MQTT会话，唤醒后需重新初始化、连接并恢复业务；不能把它当成持续在线模式。
- Light-sleep与Wi-Fi省电策略的实际可用性和唤醒延迟必须在当前ESP-IDF版本、接线和网络条件下板载验证。
- 舵机切断供电可能失去保持力矩；只能在确认机械结构、负载和安全位满足要求时试验，并增加恢复供电后的重初始化流程。
- 不仅测平均电流，也测**峰值电流、唤醒/重连时间、STOP响应、丢命令情况**。

### 3.2 ESP32-S3：ACTIVE / IDLE / SLEEP

| 状态 | 进入条件（拟定） | 可采取措施 | 唤醒/退出条件 |
|---|---|---|---|
| ACTIVE | 正在识别/控制或最近有用户操作 | 正常采样、OLED反馈、MQTT在线；优先响应STOP | 一定时间无有效操作转IDLE |
| IDLE | 无有效动作且通信健康 | 降低姿态采样频率；OLED降低刷新或熄屏；事件驱动发布、不重复发送无变化命令；测试Wi-Fi Modem-sleep | 按键、运动/姿态变化或新业务事件返回ACTIVE |
| SLEEP（可选） | 长时间无人使用且允许离线 | 先发布状态并完成必要清理；评估Light-sleep/Deep-sleep及唤醒源 | 定时器/已验证的按键或传感器中断唤醒，重新初始化与联网 |

实施注意：

- ESP-IDF Wi-Fi Modem-sleep可通过 `esp_wifi_set_ps()` 配置，但某些IDF配置的默认值本来就是省电模式。**必须先读当前配置、测基线，不能把“调用API”当成节电成果。**
- 若计划用MPU6050中断唤醒，先确认实际模块INT接线、GPIO与所选睡眠模式支持的唤醒能力。
- 不要为省电而降低STOP检测频率到不可接受；阈值、时间窗口、采样频率要结合误识别率实测调整。

### 3.3 STM32F407和舵机供电

1. 先将阻塞式 `HAL_Delay()` 步进改为**定时节拍驱动的非阻塞状态机**，主循环持续处理串口和STOP。
2. 空闲时在确认所有待处理事件、时钟和中断唤醒条件后，评估WFI/Sleep；先不直接切Stop模式。
3. 舵机动作完成后按照实际负载区分“需保持力矩”和“可安全释放”；不在抓取承重时断电。
4. 单独测量5V舵机电源支路的待机、动作和堵转/过载情况，评估是否需要INA219/INA226等独立监测。

### 3.4 测试方法与记录模板

每组测试固定：固件版本、供电电压、接线、Wi-Fi AP与信号条件、MQTT参数、采样率、OLED状态、舵机负载、采样时间。

| 场景 | ESP32平均电流(mA) | ESP32峰值(mA) | 舵机支路平均/峰值(mA) | 命令延迟(ms) | STOP响应(ms) | 备注 |
|---|---:|---:|---:|---:|---:|---|
| 当前基线 ACTIVE | 待测 | 待测 | 待测 | 待测 | 待测 | 固件版本：____ |
| IDLE（降低采样/刷新） | 待测 | 待测 | 待测 | 待测 | 待测 | 参数：____ |
| Wi-Fi省电配置对照 | 待测 | 待测 | 待测 | 待测 | 待测 | 当前PS设置：____ |
| 休眠和唤醒 | 待测 | 待测 | 待测 | 待测 | 待测 | 重连耗时：____ |

计算：

`节电率 = (基线平均电流 - 优化后平均电流) / 基线平均电流 × 100%`

记录测量设备、时间窗口及重复次数；不填写主观估计。

**低功耗验收条件：**有同条件对照数据；没有异常重复命令；可恢复联网/业务；STOP响应不因省电策略明显恶化；不产生舵机失控或负载跌落。

## 4. OTA升级可靠性

### 目标流程

```text
运行分区A → 版本/设备检查 → HTTPS下载新镜像到备用B
→ 完整性校验 → 设置启动分区 → 重启 → 新APP自检/确认
→ 成功保留新版本；失败按分区表及rollback配置恢复
```

**执行任务：**

- [ ] 核对分区表：factory/ota_0/ota_1/otadata及镜像容量。
- [ ] 复核 `esp_ota_get_running_partition()`、`esp_ota_get_next_update_partition()`、`esp_ota_begin/write/end/set_boot_partition()` 的错误路径。
- [ ] 下载阶段加入版本检查、长度与写入结果核对，并选用经过证书校验的传输方式。
- [ ] 新固件首次启动执行基本自检；如启用IDF rollback机制，按该版本SDK要求确认新镜像有效。
- [ ] 实测：正常升级、错误镜像、下载中断、写入中断、首次启动失败、回滚与旧版保留。

**注意：**A/B分区并不自动等于“已完成可靠回滚”；分区表、bootloader配置、校验及启动确认都要验证。

## 5. STM32执行端：非阻塞状态机与STOP

建议状态：

`IDLE / OPENING / GRABBING / RELEASING / STOPPING / FAULT`

- UART接收只负责存储数据、形成待处理事件，不在中断里做长时间舵机动作。
- 定时器或系统Tick驱动每个手指按步长更新目标角度，不在动作函数内长时间阻塞。
- 收到STOP后取消当前动作序列，进入预定义安全策略；明确“保持当前位置”和“回90°安全位”是两种不同策略，按结构和负载验证。
- I²C失败、动作超时、通信超时进入可记录的故障状态。

**验收：**执行GRAB途中发送STOP，测量从完整命令接收到停止继续执行原动作的延迟；重复测试并保存逻辑分析仪/串口日志。未经验证不使用“硬件急停”或“零延迟急停”表述。

## 6. 可靠通信：帧协议、ACK、seq和去重

当前主链与升级实验要明确区分。可保留现有 `HAND_GRAB\n` 字符串协议作为兼容路径，新协议先独立验证后再切换。

建议候选二进制帧（格式以联调结果为准）：

```text
HEAD | VER | LEN | SEQ | CMD | PAYLOAD | CRC | TAIL
```

- `LEN`：定义明确的覆盖范围并限制最大长度；`CRC`：错误检测，不代表加密认证。
- DMA负责UART→内存搬运，IDLE只提示线路空闲；真正消息边界由长度/状态机/校验决定。
- Linux网关发送带seq命令；STM32按seq匹配并返回业务ACK（含接收/执行状态）；ACK与MQTT QoS1 PUBACK区分。
- 超时可重试，但执行端应在明确的去重窗口内对重复请求**不重复执行，只重发已有结果**。
- 要考虑seq重启/回绕、不同设备或会话、ACK丢失、动作进行中同seq重发及STOP优先级。

**验收用例：**正常命令、非法cmd、半帧/粘帧、CRC错误、ACK丢失、同seq重复、断线重连、执行中STOP；用日志证明每次实际动作次数与ACK一致。

## 7. 传感器反馈、健康监控与安全

### 7.1 抓握反馈（可选硬件扩展）

- FSR/薄膜压力传感器：先标定零点、量程与重复性，再通过STM32 ADC（可结合DMA）采样和滤波。
- 抓取时逐步闭合，达到经实测设定的接触阈值后停止该指继续闭合；未标定前不要把原始ADC值直接叫“牛顿力值”。
- ToF可作接近检测；INA219/INA226可作供电支路监测，但它们并不能直接提供每个手指的独立受力或每个舵机的独立堵转状态。

### 7.2 故障与看门狗

- 故障码建议：`FAULT_I2C / FAULT_UART / FAULT_SENSOR / FAULT_ACTION_TIMEOUT / FAULT_POWER`。
- 关键模块/任务心跳确认后再喂狗；不要用独立高优先级任务无条件喂狗掩盖业务卡死。
- 断线后的恢复过程需要明确恢复状态，避免重连后自动重复执行旧控制命令。

## 8. NVS、安全通信和ROS2最小闭环

- NVS：设备ID、采样/识别阈值、Broker地址等可配置参数，写入后提交；凭据使用受控配置，不把真实密码提交到GitHub。
- MQTT安全：验证TLS证书链、设备认证与异常重连；TLS Demo完成不等于整机已接入安全通信。
- ROS2 Humble：先完成 `/hand_command` → Linux Gateway → UART → STM32；再把执行状态上报至 `/hand_status`。保留原MQTT路径，不因新增ROS2破坏已可运行主链。
